# Checklist penyelesaian backend sampai production

**Kesiapan production yang sudah terbukti: 21% (10 dari 47 gerbang).**
**Sisa: 37 gerbang.** Diperbarui 4 Oktober 2026 (Asia/Jakarta).

## Cara membaca persentase

Angka ini mengukur gerbang kesiapan rilis yang sudah punya bukti, bukan banyaknya file/kode yang sudah dibuat atau perkiraan jam kerja. Satu gerbang bernilai sama; persentase = jumlah kotak `[x]` dibagi 47, dibulatkan ke persen terdekat. Untuk gate fitur, bukti acceptance E2E memakai PostgreSQL nyata, HTTP, sesi dan role nyata cukup untuk menutup perilaku domain; bukti deploy/operasi live dicatat terpisah dan tetap wajib sebelum mengaktifkan fitur bagi pengguna. Harness memakai DB loopback `*_test` secara default; mode demo hanya aktif dengan opt-in eksplisit, tidak menjalankan migrasi/seed, memeriksa checksum skema, dan menekan outbox milik data uji sebelum worker dilanjutkan. Smoke test atau unit test tidak dianggap sebagai bukti end-to-end. Angka akan dihitung ulang setiap kotak berubah. Audit seluruh 31 Markdown di `docs/` selesai; temuan yang butuh perbaikan/sinkronisasi tetap terbuka pada gerbang terkait. Full `npm run check` sebelumnya lulus: 208 tes API lulus, 3 dilewati (2 membutuhkan Redis lokal dan 1 E2E membutuhkan env DB), worker 69, config 8, Hermes 5, build serta route checker 129/129. Pada revisi ini, TypeScript test dan E2E demo DB lulus; dua E2E loopback terdahulu juga lulus. Gate G-27 dan G-32 tuntas untuk acceptance backend, sedangkan 9 gate komunitas lainnya masih terbuka.

**Status saat ini:** ada kode dan automated tests untuk banyak fitur; beberapa smoke/health/route check deployment juga pernah lulus. E2E komunitas/relawan/dampak menjalankan dua workflow HTTP dengan sesi/role nyata: dua run pada PostgreSQL loopback test dan satu run pada DB demo deployment dengan source lokal, HTTP Hermes fixture dan storage stub. Pada run demo, worker dijeda sebentar lalu dinyalakan kembali; 99 event outbox milik data uji ditandai delivered, dan pemeriksaan pasca-start menunjukkan 0 event terbuka serta 0 review queued/running. API/web tidak direstart, tidak ada migrasi/seed/provider live, dan data sintetik dibiarkan di DB sesuai izin. Acceptance backend G-27 dan G-32 lengkap; G-28–G-36/G-47 masih parsial. Angka 21% bukan klaim bahwa hanya 21% kodenya sudah ada atau bahwa komunitas sudah diaktifkan di deployment.

## Perbaikan lokal yang sudah dilakukan

Kotak di bagian ini mencatat perbaikan kode dan tes fokus. Ini **tidak** dihitung sebagai gerbang production, karena tesnya belum mencakup alur nyata dengan database/provider/user production.

- [x] Vision ML sekarang menerapkan batas waktu sampai body JSON selesai dan menolak nilai confidence kosong/tidak finite/di luar 0–1. Suite worker fokus lulus **61/61**.
- [x] Perubahan status kegiatan tidak mengirim pemberitahuan perubahan kepada anggota yang sudah batal; pembatalan memberi kabar kepada peserta aktif saat dibatalkan dan koordinator. Tes layanan kegiatan lulus **3/3** memakai SQL mock.
- [x] Pencabutan consent Instagram menjaga operasi retract `failed`/`needs_action` untuk pemulihan eksplisit dan tidak membuat post seolah aman terhapus. Tes regression lulus **4/4** memakai SQL mock.
- [x] Pemilihan media draft Instagram kini mencocokkan tipe dan ID subjek sehingga aset kejadian lain tidak terselip. Tes selector lulus **2/2**.
- [x] Login MFA: percobaan TOTP valid ke-5 sebelumnya tertolak karena batas SQL memakai `< 5` setelah nomor percobaan dinaikkan. Batas transaksi diperbaiki dan regression suite MFA lulus **12/12**; ini belum menggantikan tes PostgreSQL nyata atau E2E login.
- [x] OTP/reset password: penerbitan challenge per email+tujuan kini diserialisasi dan reuse cooldown atomik; percobaan salah dibatasi di SQL; reset password, konsumsi OTP, dan pencabutan sesi dikelompokkan satu transaksi; ganti password memastikan sesi peminta masih aktif lalu mencabut sesi lain dalam transaksi. Typecheck API dan tes API lulus **194/194**. Ini bukti level kode/mocks, belum tes concurrency/rollback PostgreSQL nyata; pengiriman Resend masih inline tanpa outbox/retry.
- [x] Harness E2E komunitas/relawan/dampak memakai HTTP API, sesi dan role pengguna/admin nyata, serta Hermes HTTP fixture lokal. Mode default memakai PostgreSQL test loopback (`*_test`) dan telah lulus **3/3 test node pada 2 run berurutan**. Mode demo memerlukan `SAP_E2E_ALLOW_DEMO_DATABASE=1`; memverifikasi seluruh checksum migrasi dan kategori dengan query baca-saja, melewati migrate/seed, lalu menandai event test-owned delivered dan review queued sebagai superseded agar worker live tak menjalankannya. Pada 4 Oktober 2026 kedua workflow lulus **3/3 node** terhadap DB demo deployment; worker dijeda lalu dipulihkan, 99 event ditahan dari replay, dan sesudah start tidak ada outbox/review terbuka. Data tes tetap tersimpan sesuai izin; Hermes dan object storage tetap fixture/stub, jadi ini bukan deploy atau provider-live E2E.
- [ ] Pemulihan scan antrean: perubahan kuota/idempotency lokal sudah dibuat; durable outbox, lease, fencing, dan tes Postgres/Redis belum tersedia. Batas re-run bila worker crash dan kode hasil terminal perlu diputuskan dari kontrak sebelum implementasi.

- [ ] **G-15 — Akun R1:** minimisasi data, sesi, ekspor/hapus sesuai kontrak, otorisasi resource lain dan efek samping teruji end-to-end.
- [ ] **G-16 — Akun R2:** alur email OTP/reset harus benar-benar diterima dan salah/expired/resend diuji E2E. Perbaikan lokal sudah membuat challenge/resend serialized dan reset/ganti password + pencabutan sesi transaksional; baru lulus typecheck/API tests level kode. Pengiriman Resend tetap inline setelah challenge disimpan, tanpa outbox/retry (provider gagal bisa membuat pengguna menunggu cooldown sebelum meminta kode baru); tes delivery/provider, concurrency/rollback PostgreSQL, dan alur browser masih wajib.
- [ ] **G-17 — Akun R3:** MFA TOTP, recovery codes, revoke/session flow, lockout/rate limit, dan pemulihan akun teruji end-to-end. Bug batas percobaan TOTP valid ke-5 sudah diperbaiki lokal; tes layanan saat ini mock, belum membuktikan transaksi PostgreSQL/race di production. Tes OTP juga perlu memastikan hitungan batas tahan terhadap request paralel.
- [ ] **G-18 — Akun R4:** upload avatar, validasi file, akses private/signed URL, penggantian dan penghapusan media teruji end-to-end.
- [ ] **G-19 — Layanan eksternal:** email transactional dan siklus R2 upload, signed read, delete, serta kegagalan provider benar-benar teruji. Temuan kode: loop pembacaan body dari R2 di worker tidak punya deadline sesudah response `send` berhasil; tambahkan timeout/cancel yang mencakup pembacaan body dan tes aliran terputus.
- [ ] **G-20 — Backup/restore dan penghapusan:** lakukan restore drill pada database hasil restore yang terisolasi—jangan restore snapshot menimpa production aktif. `DATABASE.md` mewajibkan tombstone penghapusan yang bisa diputar ulang, tetapi tombstone saat ini hidup di snapshot database yang sama; restore dari snapshot sebelum penghapusan bisa kehilangan tombstone dan menghidupkan kembali data terhapus. Butuh sumber erasure append-only di luar failure domain backup DB, atau prosedur restore dengan ingress tetap tertutup sampai seluruh erasure setelah snapshot diputar ulang, serta tes negative-control deletion-after-backup. Backup/restore production belum teruji.
- [ ] **G-21 — Keamanan/performa/operasi production:** jalankan skenario security, rate limit, akses silang, beban, resource limits, serta alert/queue-age. Temuan kode: `GET /health` menggabungkan readiness dengan status proses, hanya gagal bila DB mati, menyembunyikan komponen Redis/R2 yang gagal; API/worker belum punya liveness/readiness terpisah dan worker heartbeat. R2 `HeadBucket` hanya membuktikan visibilitas bucket, bukan upload. `CONTENT_OPERATIONS.md` belum menetapkan admin operasional/escalation owner dan seluruh checklist pembukaan masih kosong. Buat health terpisah dan tes dependency matrix tanpa mematikan pembacaan yang aman; tetapkan moderator/escalation serta izin live-data pilot dari kebijakan yang disetujui, lalu buktikan runbook/deployment.

### SAPA assistant dan Account

- [ ] **G-22 — SAPA R1/R2:** browser → API → provider, jawaban berbasis sumber, abstention saat tidak tahu, prompt injection, timeout/provider mati dan fallback manusia diuji.
- [ ] **G-23 — SAPA RAG:** evaluasi berbahasa Indonesia dengan expected sources, relevansi, sitasi, abstention dan regresi; bukan hanya tes bahwa embedding/provider merespons. Kode saat ini belum punya registry sumber dengan bahasa/tanggal review/versi/lisensi/status aktif dan belum menerapkan threshold relevansi yang dievaluasi; jangan jawab klaim poin/badge/ambang peta yang masih `TODO-VERIFIKASI` seolah fakta.
- [ ] **G-24 — SAPA R3/R4:** dokumen berbeda pendapat apakah domain read-only tools tersedia; source SAPA saat ini menyediakan tools baca, sedangkan policy pilot/izin belum dibuktikan. Selaraskan kontrak, dokumen, allowlist dan akses data; tool action tetap memerlukan persetujuan manusia. Buktikan pembatasan, audit, dan kill switch bila fitur ini masuk scope rilis.
- [ ] **G-25 — SAPA R5:** batas biaya, durasi, kuota, retry, health/provider degradation, retention, dan metrik teruji serta terlihat operator. Rate counter Redis kini menaikkan hitungan dan memasang TTL dalam satu Lua script; tes Redis nyata membuktikan 100 increment paralel, TTL non-sliding, dan perbaikan key legacy. Serialisasi turn per conversation/deduplikasi retry masih ditangani terpisah dan belum terbukti; provider/error/cost/replay/operasional juga masih terbuka.
- [ ] **G-26 — Alur akun lengkap:** gabungkan ACCOUNT-R1–R4 melalui UI/API memakai sesi nyata; semua aksi pengguna dan admin serta invalidasi cache/session lolos.

### Komunitas, relawan, dan dampak

- [x] **G-27 — Dukungan/follow:** E2E PostgreSQL membuktikan desired-state/concurrent retry, pencabutan dukungan, penolakan bagi email belum verified, batas akun 60 request/menit, follow/unfollow, transfer dukungan/follow unik saat canonical merge, report revision dan agregat peta tetap, serta tidak ada poin/risk dari dukungan. Leaderboard dukungan dan hadiah vote memang ditunda oleh riset; bukan prasyarat R1. Ini menutup acceptance backend, bukan bukti deploy/operasi live.
- [ ] **G-28 — Pembaruan kondisi:** E2E membuktikan submit teks+foto, revisi, pending privat, larangan pending ganda, request-evidence→revisi→review snapshot baru, koreksi `information_wrong` dengan `correctionField` dan rendition publik, approval/public timeline dan signed public rendition tanpa private key. Reject, variasi ownership media dan semua konflik/replay masih belum diuji.
- [ ] **G-29 — Review manusia:** E2E worker memakai Hermes HTTP fixture lokal untuk report/update/result, menyimpan `review_runs`, fence snapshot usang, menjalankan request-evidence→revisi→review snapshot baru, membiarkan moderator mengalahkan saran `human_review`, dan memproses keputusan manual saat update provider memberi 503. Belum mencakup reject/retry/invalid/timeout untuk seluruh task, recovery/queue failure dan fallback menyeluruh.
- [ ] **G-30 — Proyeksi publik dan peta:** E2E membuktikan pending update tak masuk timeline, approved evidence memakai rendition publik, incident/timeline tidak memuat exact GPS, detail withdrawn 410, duplicate redirect, private hold reason tak bocor, serta map kembali sama dengan baseline setelah duplicate/withdraw. List/detail/cache snapshot dan invalidasi lintas semua route masih terbuka.
- [ ] **G-31 — Siklus kegiatan:** E2E membuktikan create, coordinator acceptance, publish, edit/jadwal, close/start, cancel dan scope coordinator; alasan pembatalan publik aman dan internal hold reason privat. Hold/resume dan transisi/error lengkap belum diuji. Migration 0017/0018 telah diverifikasi terpasang di DB demo deployment dengan checksum cocok; aplikasi belum di-deploy ulang.
- [x] **G-32 — Keanggotaan dan kapasitas:** E2E PostgreSQL membuktikan penolakan join setelah deadline, dua acceptance serentak untuk satu kursi menghasilkan satu diterima/satu `ACTIVITY_FULL`, cancel/rejoin memakai membership unik, promosi waitlist setelah kursi bebas, schedule acknowledgement, attendance absent→present, dan koreksi attendance setelah result approved. Penerimaan backend lengkap; uji kapasitas lintas proses/deployment tetap di gate operasi umum, bukan blocker domain ini.
- [ ] **G-33 — Kehadiran dan hasil:** E2E membuktikan attendance correction absent→present, bukti before/after, Hermes result review, request-evidence→revisi→review baru, hasil partial, serta complete dengan public rendition dan keputusan admin; partial maupun complete result approval tidak mengubah status report otomatis. Complete activity claim dipakai pada resolusi eksplisit. Reject/revisi lain dan lifecycle penuh masih wajib.
- [ ] **G-34 — Resolusi dari bukti:** E2E membuktikan update claim lama dicabut oleh observasi baru, claim revoked ditolak, claim baru dari community update maupun activity-result complete dipakai untuk resolusi eksplisit, partial tak menyelesaikan report, dan poin dibalik saat withdraw. Kode juga kini mencabut claim ketika consent/approval web sumber dicabut serta mengabaikan claim tanpa izin publik aktif; uji regresi jalur izin dan konsistensi seluruh timeline/audit/outbox/replay masih perlu assertion.
- [ ] **G-35 — Dampak:** metodologi tetap: `verifiedKg` hanya dihitung sesudah ada `activity_result` approved dan report source eligible; verifikasi measurement adalah keputusan terpisah. E2E PostgreSQL membuktikan pending-result menghasilkan `null`, approved zero menghasilkan `0`, tiga tahap pada satu batch terpisah, koreksi verified `2.5 → 2.25` supersede nilai lama (tidak dijumlahkan ganda), recycled weight, attendance present masuk coverage, dua hasil approved dihitung, serta bobot tetap eligible setelah report resolved. Multi-batch/canonical, withdrawal/private, correction race dan anti-double-count lintas dataset masih harus diuji.
- [ ] **G-36 — Notifikasi:** E2E PostgreSQL membuktikan penerima aktif mendapat cancel notice yang tidak terduplikasi oleh replay command, user lain tak dapat membaca notifikasi itu, hasil approved memberi notice, dan read menghilangkannya dari unread. Kode kini mengirim notifikasi keputusan pembaruan kondisi ke pengirim, perkembangan publik/withdrawal ke follower, serta notice aman ke peserta/koordinator saat sumber ditarik; E2E untuk deduplikasi follower/community/withdrawal, target link allowlist dan seluruh state recipient masih terbuka.
- [ ] **G-47 — Lifecycle laporan baseline:** E2E membuktikan create/edit, verify/duplicate/canonical merge, resolved/reject, support/follow projection, map/timeline, award/reversal dasar, dan replay keputusan verify tanpa revision/award ganda. Badge/streak/leaderboard, cap harian, replay untuk seluruh transisi/idempotency conflict, kompensasi lintas hari dan sinkronisasi seluruh proyeksi masih belum lengkap.

## Urutan kerja berikutnya

1. Selesaikan audit semua dokumen dan kunci daftar acceptance/konflik di bagian atas checklist.
2. Perbaiki temuan konkret berisiko tinggi: pemulihan scan queue, parsing/timeout ML, erasure tombstone saat restore, notifikasi anggota cancelled, dan mismatch adapter Instagram.
3. Tambahkan integration tests dengan Postgres/Redis/Gradio/Hermes yang benar untuk perilaku concurrency, recovery, review persistence, dan scan lifecycle.
4. Jalankan tes yang dapat dibuktikan lokal; catat output/commit dan perbarui [laporan pengujian production](PRODUCTION_BACKEND_TEST_REPORT_2026-10-04.md).
5. Jalankan acceptance yang diizinkan di production dengan identitas dan aset test yang sah; jangan memasukkan data sintetis seolah-olah insiden nyata.
6. Selesaikan review deployment/restore/monitoring lalu hitung ulang persentase. Jangan menyebut 100% sebelum semua gerbang yang berlaku lulus.
